# 🌕 中秋餐會 座位與餐點登記系統

| 檔案 | 用途 |
|---|---|
| `index.html` | **登記表單**：給同仁的頁面，只有登記與各桌剩餘座位（同仁不能自己修改或刪除） |
| `admin.html` | **福委後台**：登記進度、待配對名單、點餐統計、各桌名單、匯出 CSV |
| `config.js` | 兩個頁面共用的設定（後端網址、報名人數、桌次、餐點選項） |
| `shared.js` | 兩個頁面共用的程式（資料存取、工具函式） |
| `style.css` | 兩個頁面共用的樣式 |
| `Code.gs` | Google Apps Script 後端，資料存進 Google 試算表，含防超賣鎖 |

> 表單頁不會連到福委後台。福委請直接開 `…/admin.html`（網址不要貼到同仁群組）。
> 注意：這只是「不公開連結」，並不是真正的權限控管。登記資料透過後端 API 仍然讀得到，所以不要在表單裡收集敏感資料。

## 登記流程

首頁上方並列三個按鈕：**👫 兩人一組登記**、**🌱 素食桌登記**、**🙋 找不到搭檔**。兩人一組也可以直接在下方桌卡按「登記這桌」。

```
            ┌─ 👫 兩人一組登記（或桌卡「登記這桌」）──────────┐
            │  選桌次（必選；也可選「不指定，由福委安排座位」） │
            │  ① 兩位成員：姓名 + 工號                        │
            │  ② 主餐套餐：牛豚 / 全豚 / 素（兩人共用）         │
同仁進入 ──┤  ③ 細項：海鮮（兩人共用，素食自動跳過）           │── 顯示登記內容
            │          飲品、甜點（每人各選）                   │   按「確認」才關閉
            │  ＋ 同桌再加一組（可一次登記整桌）                │
            ├─ 🌱 素食桌登記（一人一位）──────────────────────┤
            │  ① 姓名 + 工號  ② 飲品、甜點                     │
            │  主餐自動為「素」，不用選海鮮；可幫同事一起登記   │
            ├─ 🙋 找不到搭檔 ────────────────────────────────┤
            │  一人填寫資料 + 主餐/海鮮偏好 + 飲品/甜點         │── 進入「待配對」名單
            └────────────────────────────────────────────────┘
```

同仁送出後**不能自己修改或刪除**，需要異動時請洽福委會，由福委直接改試算表。

## ⚠️ 開放登記前要先處理

### 1. 座位與人數

| 桌型 | 桌號 | 張數 | 小計 | 登記方式 |
|---|---|---:|---:|---|
| 4 人桌 | A1～A6、B1、B2 | 8 | 32 | 兩人一組，每桌 2 組 |
| 🌱 素桌（6 人） | B3 | 1 | 6 | 一人一位 |
| 8 人桌 | B4 | 1 | 8 | 兩人一組，每桌 4 組 |
| 6 人桌 | C1～C8 | 8 | 48 | 兩人一組，每桌 3 組 |
| **合計** | | **18** | **94 席** | |

報名 **93 人**，座位足夠（多 1 席）。

素桌坐滿 6 人後，其餘 **87 人是單數**，兩人一組一定會有 **1 人湊不成對**，請福委事先想好怎麼處理（例如與福委同組，或跟餐廳確認能不能點單人套餐）。福委後台會一直顯示這個提醒。

### 2. 設定要兩邊一致

`config.js` 和 `Code.gs` 開頭各有一份 **`TABLE_CONFIG`（桌次）**、**`VEG_FIXED`（素桌自動帶入的餐點）** 和 **`MENU`（餐點選項）**，**改的時候兩邊要一起改**。報名人數 `EXPECTED_TOTAL` 只在 `config.js`。

`TABLE_CONFIG` 是一桌一行，對應餐廳的桌號標示（例如「A1 4P」）：

```js
{ id: 'A1', size: 4 },
{ id: 'B3', size: 6, veg: true },   // 素桌
```

要加桌就多加一行，要換素桌就把 `veg: true` 移到另一行。

> ⚠️ 已經有人登記的桌號，不要改名或從 `TABLE_CONFIG` 移除，否則那些人會從頁面上消失（資料還在試算表裡）。福委後台會列出「桌號不在桌次設定裡」的登記，方便找出來修正。

後端會驗證每一個選項，如果只改了前端，同仁送出時會看到「選項無效」。

## 餐點選項怎麼改

`MENU` 裡每一項長這樣：

```js
{ key: 'seafood', label: '海鮮', per: 'pair', step: 3,
  options: ['干貝/大蝦', '干貝/花枝'],
  skipIf: { main: '素' }, skipNote: '素食套餐不含海鮮，不用選' },
```

| 欄位 | 意思 |
|---|---|
| `options` | 選項文字，直接增減即可 |
| `per` | `'pair'` = 一組兩人共用一份；`'person'` = 每人各選一份 |
| `step` | 顯示在表單第 2 步（主餐套餐）或第 3 步（細項） |
| `skipIf` | 符合條件時這一項不用選，例如主餐選「素」就跳過海鮮 |

選項 4 個以內會顯示成按鈕，超過 4 個（例如飲品）會顯示成下拉選單。

> ⚠️ 已經有人登記之後，**不要改既有選項的文字**（例如把「冰棒」改成「雪糕」），舊資料會對不上統計。新增選項沒問題。

## 要不要資料庫？

**不用。** 但也不能只用一個 Excel 檔。

關鍵在「**被預訂就要扣掉數量，讓其他人無法預約**」。兩組人同時搶最後一個位子時，系統必須只讓一組成功。共用資料夾裡的 `.xlsx` 做不到，後存檔的人會直接蓋掉前一個人的資料。

**Google 試算表 + Apps Script** 剛好兩全：

- 資料就是一張試算表，福委隨時可以開來看、排序、匯出 Excel ✅
- Apps Script 的 `LockService` 提供真正的互斥鎖，不會超賣 ✅
- 免費、不用主機、不用維運 ✅

## 部署步驟（約 10 分鐘）

### 1. 建立試算表與後端

1. 開 [sheets.new](https://sheets.new) 建立空白試算表，命名為「中秋餐會報名」
2. 選單 **擴充功能 → Apps Script**
3. 把編輯器裡原本的 `function myFunction() {}` 全部刪掉，貼上 `Code.gs` 的完整內容
4. 存檔（Ctrl+S）

### 2. 部署成網頁應用程式

1. 右上角 **部署 → 新增部署作業**
2. 齒輪圖示 → 選 **網頁應用程式**
3. 設定：
   - 執行身分：**我**
   - 誰可以存取：**任何人**（若只給公司內部用，可選「{貴公司網域} 的所有人」，但同事必須先登入公司 Google 帳號）
4. 按 **部署**，第一次會要求授權 → 允許
5. 複製產生的網址（`https://script.google.com/macros/s/AKfy.../exec`）

### 3. 接上前端

打開 `config.js`，第 8 行：

```js
const API_URL = '';   // ← 把剛剛複製的 /exec 網址貼進這裡的引號中
```

### 4. 把頁面放上網

要上傳這 5 個檔案，**放在同一個資料夾**：`index.html`、`admin.html`、`config.js`、`shared.js`、`style.css`（`Code.gs` 和 `.claude` 資料夾不用傳）。任選一種方式：

- **最快**：到 [app.netlify.com/drop](https://app.netlify.com/drop) 把整個資料夾拖進去，30 秒拿到公開網址
- **GitHub Pages**：上傳到 repo → Settings → Pages → 啟用
- **公司內網**：丟到任何能放靜態檔的地方即可

> 直接雙擊用 `file://` 開啟也能跑，但部分瀏覽器會擋跨網域請求，正式使用請用上面任一種方式架起來。

### 5. 驗收

把網址丟到群組前，自己先測一遍：

1. 兩人一組登記 4 人桌 → 該桌剩 2 位 ✅
2. 用**另一台裝置**開同一個網址 → 看得到剛剛那組 ✅
3. 同一桌再登記 2 組 → 應被擋下「只剩 2 個位子」 ✅
4. 主餐選「素」→ 海鮮自動變成「不用選」 ✅
5. 用同一個工號再登記一次 → 應被擋下 ✅
6. 「🌱 素食桌登記」→ 只要填姓名、工號、飲品、甜點；B3 桌剩餘座位減少 ✅
7. 「找不到搭檔」登記 → 福委後台（`admin.html`）的「待配對」名單出現這個人 ✅
8. 登記完成視窗按 Esc 不會關，要按「確認」才會關 ✅
9. 福委後台的點餐統計數字和剛剛登記的內容相符 ✅
10. 測完後到試算表把測試資料那幾列刪掉 ✅

## 試算表欄位

系統會自動建立「報名紀錄」工作表，**一人一列**：

| 登記時間 | 預約碼 | 桌號 | 組別 | 姓名 | 工號 | 主餐套餐 | 海鮮 | 飲品 | 甜點 |
|---|---|---|---|---|---|---|---|---|---|
| … | K7F2QX | A1 | K7F2QX-1 | 王小明 | E001 | 牛豚 | 干貝/大蝦 | 紅茶 | 手工塔 |
| … | K7F2QX | A1 | K7F2QX-1 | 陳美玲 | E002 | 牛豚 | 干貝/大蝦 | 可樂 | 冰棒 |
| … | H4NW2D | B3 |  | 林素華 | E020 | 素 |  | 烏龍茶 | 紅豆湯 |
| … | P3MZ8R |  |  | 林小華 | E030 | 全豚 | 干貝/花枝 | 烏龍茶 | 紅豆湯 |

- **預約碼**：同一次送出的登記編號，系統內部用來串起同一次送出的資料，**同仁看不到**，也不需要保存
- **組別**相同的兩人是同一組
- **組別空白、桌號是素桌** = 素桌（一人一位）
- **組別空白、桌號空白** = 找不到搭檔、待配對
- **組別有值、桌號空白** = 已組隊、待福委排座位

試算表選單 **🌕 餐會工具 → 產生座位與點餐總表** 會產生「總表」工作表，內容有各桌名單、待配對名單，以及**要給餐廳的點餐數量**。

## 福委會怎麼配對、排座位

直接在「報名紀錄」工作表修改。福委後台按「重新整理」會立刻看到；表單頁約 1 分鐘內會更新：

1. **配對兩位待配對同仁**：把兩人的「組別」填成同一個值（例如 `福委-1`），並把兩人的「主餐套餐」「海鮮」改成一樣
2. **排座位**：在「桌號」填入 `A3`、`C5` 等（大寫英文＋數字，要和桌次設定完全一樣）
3. **把人排進素桌**：「桌號」填 `B3`、「組別」留空、「主餐套餐」填 `素`、「海鮮」留空
4. **同仁要改餐點或取消**：直接改該列的內容，或刪掉那一列

> 手動改的時候系統不會檢查容量，請留意每桌人數，可以用「總表」確認。

## 常見狀況

**改了 `Code.gs` 之後前端沒反應**
Apps Script 每次改完要重新部署：**部署 → 管理部署作業 → 編輯（鉛筆）→ 版本選「新版本」→ 部署**。網址不會變。

**頁面出現「工作表的欄位和程式不一致」**
試算表裡有舊版格式的「報名紀錄」工作表。把它改名（例如「報名紀錄_舊」），系統會自動建立新的。

**很多人同時送出會不會出問題？（併發處理）**
不會超賣，也不會重複登記：

| 情況 | 處理方式 |
|---|---|
| 兩組人同時搶最後幾個位子 | 後端讀取→檢查→寫入全程上鎖，一次只處理一筆，後到的會看到「只剩 N 個位子」 |
| 排隊的人太多，等不到鎖 | 後端回傳「請重試」，前端自動重試最多 4 次，每次間隔逐漸拉長並加上隨機時間；畫面顯示「排隊中」 |
| 送出後網路逾時，其實已經寫入 | 每次送出帶一組識別碼，重送時後端回傳第一次的登記結果，不會變成兩筆 |
| Apps Script 同時執行太多、回傳錯誤頁 | 視為可重試，照上面的方式自動重試 |

座位狀態有 15 秒快取，讓讀取更快、少佔 Apps Script 的同時執行名額。福委直接修改試算表後，表單頁最多 15 秒會看到變化；福委後台不走快取，會立刻看到。

**讀取有點慢**
正常。Apps Script 每次讀取約 1.5～2 秒，閒置一段時間後的第一次可能要 3～5 秒以上。頁面已經做了這些處理：
- 先顯示上次讀到的資料，背景再更新
- 只在頁面正在被看的時候自動更新（表單頁 60 秒、福委頁 30 秒一次）
- 打開登記視窗時會更新一次座位

送出登記時後端一定會重新檢查座位，所以畫面資料稍舊也不會超賣。

**同事說「無法連線到後端」**
八成是部署時「誰可以存取」沒設成「任何人」。回到管理部署作業改設定。

**想先關閉登記**
在 `Code.gs` 的 `book_()` 開頭加一行：
```js
throw new Error('登記已截止，如需異動請洽福委');
```
重新部署即可。頁面仍可瀏覽，但送不出新登記。

**同仁想改餐點、換桌或取消**
同仁不能自己改，請洽福委會。福委直接在「報名紀錄」工作表修改或刪除該列即可（見上面「福委會怎麼配對、排座位」）。

## 未設定 API_URL 時？

頁面會進入**單機示範模式**，資料存在瀏覽器的 localStorage，換裝置就看不到。這個模式只適合自己先試玩流程，正式開放前一定要完成第 2、3 步。
